### 3.2 Encoding fill rule (`src/builder.rs:158-162`)

```rust

    Fill::NonZero => FILL_RULE_NONZERO,
```

Konstanta `FILL_RULE_NONZERO = 0`, `FILL_RULE_EVENODD = 1` (`src/builder.rs:28-29`); shift `<< 24` selaras `FILL_RULE_SHIFT: u32 = 24` (`src/builder.rs:17`). ### 3.3 Persiapan: borrow `covers`, hitung `tile_bounds`, sort `blocks`, increment `shape_index` (`src/builder.rs:163-174`)

### 3.4 Loop emisi tile dengan propagasi backdrop kiri-ke-kanan

Loop ini adalah jantung Phase 6 dari pipeline UC-03 (AC 5.1 butir e–f) dan menjadi rujukan eksplisit untuk AC 13.6.

#### 3.4.1 Inisialisasi sentinel zero (`src/builder.rs:192`)

```rust

```

Dipakai untuk membandingkan `acc_arr` (tipe `[i16; 8]` = 16 byte) lawan nol dalam satu instruksi 16-byte compare (komentar `src/builder.rs:178-188`).

#### 3.4.2 Loop baris ubin — reset akumulator di tepi kiri (`src/builder.rs:193-194`)

```rust
for row in 0..covers.rows() {
    let mut acc_arr = [0i16; TILE_H];
```

**Inilah titik yang menentukan arah propagasi: akumulator `acc_arr` di-reset menjadi `[0; TILE_H]` di awal setiap baris ubin.** Loop kolom kemudian berjalan dari `col = 0` (kolom kiri bbox) ke `col = covers.cols() - 1` (kolom kanan bbox), sehingga akumulator winding bertambah secara monotonik **kiri-ke-kanan** sepanjang satu baris ubin.

```rust

    // Fast-path: 16-byte compare vs zero rather than 8x i16 compare.
    let acc_nonzero =
        bytemuck::cast::<[i16; 8], u128>(acc_arr) != zero_acc_bits;

    if tagged || acc_nonzero {
```

Sebuah cell `(row, col)` diemisi sebagai `Tile` jika **salah satu** dari dua syarat berikut terpenuhi:

1. `tagged == true` — DDA pada `build_path` menyentuh cell ini dan menulis crossings non-nol pada minimal satu scanline (artinya ada segmen melintasi ubin ini).
2. `acc_nonzero == true` — akumulator yang dipropagasi dari kolom-kolom di sebelah kiri belum kembali ke nol pada minimal satu scanline (artinya ubin ini "interior penuh" atau "interior parsial" yang tertutup oleh shape walaupun tidak disentuh segmen di kolom ini).

Konjungsi `tagged || acc_nonzero` yang dipakai sebagai gate emisi inilah definisi operasional "ubin nontrivial" yang dipakai di Subbab 3.4.2 dan 3.5 (selaras AC 5.1, 5.2, 11.3). Tidak ada cabang `if`/`switch` berbasis tipe ubin pada lookup ini — jalur kode untuk semua ubin nontrivial tunggal.

#### 3.4.4 Body emisi `Tile` (`src/builder.rs:204-238`)

```rust
let global_x = (tile_bounds.min_col + col as i32) as u16;
let global_y = (tile_bounds.min_row + row as i32) as u16;

// Locate this tile's clipped lines in the sorted blocks vec
// and write them as RGBA32F texels into `segments`.
let (block_start, block_count) =
    find_segment_range(&self.blocks.data, global_x, global_y);

let line_offset = (self.segments.len() / 4) as u32;
for k in block_start..(block_start + block_count) {
    let b = &self.blocks.data[k];
    // Convert F24Dot8 → float pixels (tile-local).
    self.segments.extend_from_slice(&[
        b.p0x as f32 / 256.0, b.p0y as f32 / 256.0,
        b.p1x as f32 / 256.0, b.p1y as f32 / 256.0,
    ]);
}
let line_count = block_count as u32;

self.tiles.push(Tile {
    x: global_x,
    y: global_y,
    width: TILE_W as u8,
    height: TILE_H as u8,
    _pad: [0, 0],
    backdrop: acc_arr,
    segments: [
        f32::from_bits(line_offset),
        f32::from_bits(line_count),
    ],
    payload,
    paint_and_rect_flag: final_paint_flag,
    depth_index: current_depth,
});
```

Catatan kunci:

- `backdrop: acc_arr` — **nilai akumulator winding sebelum increment** disalin ke field `backdrop: [i16; 8]` pada `Tile` (lihat fakta 1.4). Artinya `backdrop` yang diunggah ke GPU mencerminkan nilai kontribusi dari semua kolom di **sebelah kiri** kolom ini pada baris ubin yang sama; kontribusi crossings dari kolom ini sendiri (jika `tagged`) ditambahkan ke `acc_arr` *setelah* `push` (butir 3.4.5).
- Konversi F24Dot8 → piksel float dilakukan dengan `b.* as f32 / 256.0` (256 = 2^8, faktor skala 8-bit fraksi).
- `segments: [f32::from_bits(line_offset), f32::from_bits(line_count)]` menyandikan dua `u32` ke dua `f32` via reinterpret-bit (bukan konversi numerik), sehingga GPU dapat membaca offset/count integer melalui `floatBitsToUint` di shader.
- `width = TILE_W as u8 = 16`, `height = TILE_H as u8 = 8` ditulis konstan untuk semua ubin yang diemisi di sini (instance penuh; klipping per piksel dilakukan oleh fragment shader).

#### 3.4.5 Akumulasi crossings via SIMD `i16x8` (`src/builder.rs:240-248`)

```rust
if tagged {
    let crossings = covers.get_crossings(row, col);
    // Single i16x8 SIMD add: replaces 8 scalar i16 adds.
    dispatch!(self.level, simd => {
        let acc_v = i16x8::from_slice(simd, &acc_arr);
        let cr_v = i16x8::from_slice(simd, &crossings);
        let sum = acc_v + cr_v;
        acc_arr = sum.into();

```

Setelah `Tile` dipush dengan `backdrop = acc_arr` lama, **jika** kolom ini tagged, `acc_arr` di-update dengan menambahkan `crossings: [i16; TILE_H]` cell ini secara per-elemen menggunakan satu instruksi SIMD `i16x8.add` (komentar `:184-188` menjelaskan ini memetakan ke satu instruksi WASM SIMD128). `acc_arr` yang sudah ter-update kemudian dibawa ke `col + 1`, mewujudkan propagasi backdrop kiri-ke-kanan: setiap ubin menerima jumlah kumulatif kontribusi winding dari semua segmen yang melintasi baris piksel di tile-tile sebelah kirinya.


## 5. Helper `find_segment_range` (`src/builder.rs:349-354`)

```rust
/// Binary search for blocks at tile position (x, y) in sorted blocks array.
fn find_segment_range(blocks: &[Block], x: u16, y: u16) -> (usize, usize) {
    let start = blocks.partition_point(|b| (b.y, b.x) < (y, x));
    let end = blocks.partition_point(|b| (b.y, b.x) <= (y, x));
    (start, end - start)
}
```

Mengandalkan urutan `(y, x)` yang ditegakkan oleh `self.blocks.sort_blocks()` (`:171`). Mengembalikan `(offset, count)` blok untuk tile pada koordinat global `(x, y)`. Inilah jembatan antara fase DDA binning (`build_path`) dan fase emisi tile (`generate_tiles`): blok yang ditulis selama Phase 5 `build_path` dibaca kembali via binary-search di Phase 6 `generate_tiles`.

## 9. Temuan untuk konsistensi internal Bab 3

1. **Nama field kanonik adalah `covers: RefCell<CoverStorage>`** (`src/builder.rs:49`), bukan `cover_storage`. Subbab 3.4.4 (Class Diagram) wajib memakai nama ini agar memenuhi AC 15.3 dan AC 15.5.
2. **Definisi operasional "ubin nontrivial"** untuk Subbab 3.4.2 dan 3.5 adalah `tagged || acc_nonzero` di `src/builder.rs:203`: ubin yang disentuh DDA atau yang akumulator winding-nya non-nol sebagai konsekuensi propagasi dari kiri.
3. **Propagasi backdrop kiri-ke-kanan adalah in-place pada `acc_arr: [i16; 8]`** di body `generate_tiles`; method `CoverStorage::propagate` (`:478`) yang tampak menjanjikan saat ini **tidak dipakai** oleh jalur eksekusi. Klaim Bab 3 wajib merujuk `Builder::generate_tiles` (`src/builder.rs:151-337`) sesuai AC 13.6, bukan `CoverStorage::propagate`.
4. **`backdrop` yang tersimpan di `Tile` adalah nilai akumulator *sebelum* increment kolom yang sedang diemisi**: `Tile.backdrop = acc_arr` ditulis pada `:230` *sebelum* `acc_arr += crossings` pada `:241-247`. Konsekuensi: shader fragment menambahkan kontribusi crossings cell ini sendiri secara analitik berdasarkan segmen yang dibaca dari tekstur RGBA32F, sementara `backdrop` hanya membawa sumbangan kumulatif dari seluruh kolom di sebelah kiri.
5. **Parameter `paint_index: u32` tidak digunakan di body `generate_tiles`** (`src/builder.rs:152`). Narasi sequence diagram (Subbab 3.4.3) sebaiknya mendeskripsikan `paint_index` sebagai konteks panggil (caller-side) atau menghapus penyebutannya, bukan mengklaim ia diproses di sini.
6. **Parameter `fill_rule: FillRule` pada `build_path` tidak digunakan di body** (`src/builder.rs:87`). Klaim fill rule pada Bab 3 wajib dilekatkan pada `generate_tiles` (yang menerima `Fill` dari `peniko` dan menyandikannya ke bit 24 `paint_and_rect_flag`) atau pada `src/render/shaders/render_tile.frag` (lihat fakta 1.5), bukan pada `build_path`.
