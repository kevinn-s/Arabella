**Verifikasi total:** 2 + 2 + 1 + 1 + 2 + 16 + 8 + 4 + 4 + 4 = **44 byte** (memenuhi AC 10.1 dan AC 10.3 pada `requirements.md`).

### 1.4 Anotasi semantik field

- `backdrop: [i16; 8]` adalah array delapan elemen 16-bit yang membawa hasil propagasi backdrop kiri-ke-kanan untuk delapan scanline pada satu ubin (selaras dengan `TILE_H = 8` di `src/blocks.rs`). Field ini menggantikan klaim "winding_number skalar" dari narasi Bab 3 lama.
- `segments: [f32; 2]` membawa pasangan rujukan ke tekstur segmen RGBA32F (sumber `(p0.x, p0.y, p1.x, p1.y)` per texel), bukan koordinat geometri.
- `width` dan `height` per-instance dapat lebih kecil dari `TILE_W × TILE_H = 16 × 8` saat ubin terletak di tepi viewport (klipping).
- Tidak ada field `winding_number` skalar, tidak ada field `curves: List<CurveRef>`, tidak ada enum `TileType`, dan tidak ada method `ray_shoot()` pada struct ini (memenuhi AC 7.3 pada `requirements.md`).

### 1.5 Penggunaan pada konstruksi tile (silang ke `src/builder.rs`)

`src/builder.rs:225-238` (cuplikan) menunjukkan inisialisasi `Tile` dengan field yang persis sama:


## 3. Struktur tekstur RGBA32F untuk segmen

**Catatan disposisi:** tugas 1.4 menyebut "struktur tekstur RGBA32F untuk segmen" sebagai bagian yang harus dicatat dari `src/render/common.rs`. Penelusuran berkas tersebut **tidak menemukan deklarasi tekstur RGBA32F**; format dan upload tekstur segmen RGBA32F sebenarnya didefinisikan di `src/render/webgl.rs`. Fakta itu didokumentasikan di sini agar Subbab 3.7 dapat memberi rujukan kode yang valid.

### 3.1 Konvensi texel (komentar verbatim, `src/render/webgl.rs:74`)

```rust
// Each LINE record is 4 floats (p0.x, p0.y, p1.x, p1.y) = 1 RGBA32F texel.
```

Komentar setara di `src/builder.rs:40-42`:

```rust
/// Each line = 4 floats in PIXEL units (p0.x, p0.y, p1.x, p1.y), all
/// expressed in tile-LOCAL coordinates so the GPU just compares with
/// `pixel_in_tile`. One RGBA32F texel per line.
```

### 3.2 Buffer field tekstur (`src/render/webgl.rs:144-153`)

```rust
/// Texture 0: curve control points (RGBA32F)
segments_texture: WebGlTexture,
segments_texture_height: u32,

/// Texture 1: per-tile segment index list (R32UI)
segment_list_texture: WebGlTexture,
segment_list_texture_height: u32,
/// Texture 2: encoded paints (RGBA32UI)
encoded_paints_texture: WebGlTexture,
encoded_paints_texture_height: u32,
```

Tekstur **0** (segmen) bertipe **RGBA32F**, tekstur **1** (daftar indeks segmen per ubin) bertipe **R32UI**, tekstur **2** (paint terenkode termasuk `GpuEncodedImage`) bertipe **RGBA32UI**.

### 3.3 Pemanggilan WebGL untuk format internal (`src/render/webgl.rs:423-446`)

```rust
fn upload_data_to_rgba32f_texture(
    gl: &WebGl2RenderingContext,
    data: &[f32],
    texture_width: u32,
    texture_height: u32,
) {
    let packed_array = unsafe { js_sys::Float32Array::view(data) };
    gl.tex_image_2d_with_i32_and_i32_and_i32_and_format_and_type_and_opt_array_buffer_view(
        WebGl2RenderingContext::TEXTURE_2D,
        0,
        WebGl2RenderingContext::RGBA32F as i32,   // internalformat
        texture_width as i32,
        texture_height as i32,
        0,
        WebGl2RenderingContext::RGBA,             // format
        WebGl2RenderingContext::FLOAT,            // type
        Some(&packed_array),
    )
    .unwrap();
}
```

**Tata letak texel:** satu texel tekstur segmen membawa empat float `(p0.x, p0.y, p1.x, p1.y)` dalam ruang piksel ubin lokal (rentang dimensi ubin 16 × 8 piksel; lihat `#define TILE_WIDTH 16u` dan `#define TILE_HEIGHT 8u` di `src/render/shaders/render_tile.frag:6-7`).

## 5. Temuan untuk konsistensi internal Bab 3

1. **Versi kanonik `Tile` adalah `src/tile.rs:9-23`**, bukan deklarasi alternatif di `src/render/common.rs:48-61` (versi `common.rs` tidak `#[repr(C)]`, memakai `backdrop: u32` skalar, dan WIDTH/HEIGHT = 4 yang tidak konsisten dengan jalur kode yang dieksekusi). Subbab 3.4.4 (Class Diagram) dan 3.7 (Database File) wajib merujuk versi `src/tile.rs`.
2. **Format tekstur segmen adalah RGBA32F**, sedangkan **format tekstur paint terenkode adalah RGBA32UI** (16-byte texel). Subbab 3.7 wajib membedakan kedua format ini saat mendeskripsikan upload GPU.
3. **Total ukuran `Tile` = 44 byte**, terverifikasi dari penjumlahan field per `#[repr(C)]`. Konsistensi numerik (Property 7) untuk klaim "44 byte per tile" dapat diandalkan.
4. Rujukan `src/render/webgl.rs:initialize_tile_vao` (yang akan dirujuk di Subbab 3.7 sesuai AC 10.4) berada di luar lingkup tugas 1.4; ekstraksi rinciannya dilakukan pada tugas 1.7.
