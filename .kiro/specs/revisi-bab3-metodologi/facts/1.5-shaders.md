# Fakta 1.5 — Shader `render_tile.frag` dan `render_tile.vert`

Dokumen ini mencatat fakta yang diekstraksi langsung (Phase 1, read-only) dari dua berkas shader pipeline rasterisasi GPU Arabella:

- `src/render/shaders/render_tile.frag` (228 baris, GLSL ES 3.00)
- `src/render/shaders/render_tile.vert` (76 baris, GLSL ES 3.00)

Semua nomor baris merujuk pada konten verbatim berkas tersebut pada saat ekstraksi. Acuan kebutuhan: 5.2, 5.3, 5.5, 8.2, 11.3, 13.7, 15.3.

## 1. Fungsi `line_box` — integral trapezoidal cakupan piksel

Fungsi ini terdeklarasi pada `src/render/shaders/render_tile.frag` baris 90. Tanda tangan dan tubuhnya disalin verbatim:

```glsl
// src/render/shaders/render_tile.frag:90
float line_box(vec2 p0, vec2 p1, vec2 pixel) {
    if (p0.y == p1.y) return 0.0;

    float sign_v;
    vec2 lo, hi;
    if (p0.y < p1.y) { sign_v = -1.0; lo = p0; hi = p1; }
    else             { sign_v = +1.0; lo = p1; hi = p0; }

    // Clip the line's y-range to the pixel's box y-extent [pixel.y ± 0.5].
    float py_lo = pixel.y - 0.5;
    float py_hi = pixel.y + 0.5;
    float y_lo  = max(lo.y, py_lo);
    float y_hi  = min(hi.y, py_hi);
    if (y_hi <= y_lo) return 0.0;

    // x-coordinates of the clipped sub-segment's endpoints.
    float dy   = hi.y - lo.y;
    float t_lo = (y_lo - lo.y) / dy;
    float t_hi = (y_hi - lo.y) / dy;
    float x_lo = mix(lo.x, hi.x, t_lo);
    float x_hi = mix(lo.x, hi.x, t_hi);

    // Trapezoidal area of the pixel-box region to the RIGHT of the line.
    float px_lo = pixel.x - 0.5;
    float px_hi = pixel.x + 0.5;
    float xc_lo = clamp(x_lo, px_lo, px_hi);
    float xc_hi = clamp(x_hi, px_lo, px_hi);
    float avg_x = (xc_lo + xc_hi) * 0.5;
    float h_cov = px_hi - avg_x;

    return sign_v * (y_hi - y_lo) * h_cov;
}
```

Tanda tangan ringkas:

```glsl
float line_box(vec2 p0, vec2 p1, vec2 pixel);   // baris 90
```

Karakteristik yang dicatat dari blok komentar di atas fungsi (`render_tile.frag:82-89`):

- Disebut sebagai **"Analytic line-area contribution (BOX filter, radius 0.5)"** (baris 83).
- Mengembalikan **fraksi bertanda dari kotak piksel 1 × 1 yang berada di sisi kanan garis** dalam rentang-y garis, diskalakan dengan tanda winding garis (baris 85-88).
- Hasil terbatas pada interval `[-1, +1]` dan secara matematis adalah konvolusi indikator setengah-bidang garis dengan filter kotak 1 × 1 yang berpusat pada `pixel` (baris 87-88).

Detail mekanis (baris 91-120):

- Garis dengan `p0.y == p1.y` (horizontal murni) langsung mengembalikan `0.0` karena tidak menyumbang cakupan (baris 91).
- Tanda winding (`sign_v`) ditentukan dari arah-y garis: `-1.0` untuk arah naik (`p0.y < p1.y`), `+1.0` untuk arah turun (baris 95-96).
- Rentang-y garis di-*clip* terhadap kotak piksel `[pixel.y − 0.5, pixel.y + 0.5]` (baris 99-103); jika hasil clip kosong (`y_hi <= y_lo`), kembalikan `0.0`.
- Endpoint sub-segmen ter-clip pada arah-x dihitung dengan parameter linear `t_lo`, `t_hi` lalu interpolasi `mix(lo.x, hi.x, t)` (baris 106-110).
- Cakupan-x diestimasi sebagai luas trapezoidal di sebelah kanan garis dengan rumus `h_cov = px_hi − avg_x` di mana `avg_x = (xc_lo + xc_hi) × 0.5` adalah rerata x ter-clamp ke kotak piksel (baris 113-118).
- Nilai akhir adalah `sign_v × (y_hi − y_lo) × h_cov` (baris 120) — produk panjang vertikal sub-segmen ter-clip dengan rerata cakupan horizontal, sesuai integrasi trapezoidal terhadap kotak piksel.

Fungsi `line_box` adalah filter cakupan baseline yang dipanggil di dalam loop akumulasi winding pada `void main()` (baris 207). Ada juga fungsi pembanding `line_tent` (baris 148) yang mengomposisi lima panggilan `line_box` sebagai approksimasi tent-filter; namun loop utama saat ini memakai `line_box` (lihat Bagian 4).

## 2. Konstanta `WINDING_UNIT` (8.8 fixed-point)

Deklarasi makro pada `src/render/shaders/render_tile.frag` baris 24:

```glsl
// src/render/shaders/render_tile.frag:23-24
// CPU stores per-scanline backdrop in 8.8 fixed-point: 256 = exactly one winding.
#define WINDING_UNIT                     256.0
```

Penggunaan satu-satunya berada di awal `main()` saat membaca backdrop per-scanline ke ruang float (`render_tile.frag:195`):

```glsl
// src/render/shaders/render_tile.frag:195
float backdrop = float(read_backdrop(scanline_row)) / WINDING_UNIT;
```

Implikasi yang dicatat:

- `WINDING_UNIT = 256.0` adalah faktor skala 8.8 fixed-point → float; nilai 256 pada akumulator integer setara satu winding penuh, sesuai komentar baris 23 (*"per-scanline backdrop in 8.8 fixed-point: 256 = exactly one winding"*) dan baris 192 (*"CPU stored 8.8 fixed-point area where ±256 = exactly one winding."*).
- Hanya komponen backdrop (yang dipropagasi CPU dari kiri-ke-kanan per baris ubin) yang melewati pembagi ini; kontribusi `line_box` sudah dalam ruang float native dan langsung dijumlahkan ke `winding` (baris 196-208).

## 3. Formula fill rule NonZero dan EvenOdd

Pemilihan fill rule dilakukan dengan satu cabang biner `if/else` pada `void main()` di `src/render/shaders/render_tile.frag` baris 213-220. Kutipan verbatim (termasuk dua makro pendukung di baris 20-21):

```glsl
// src/render/shaders/render_tile.frag:20-21
#define FILL_RULE_NONZERO                0u
#define FILL_RULE_EVENODD                1u
```

```glsl
// src/render/shaders/render_tile.frag:212-220
float coverage;
if (fill_rule == FILL_RULE_NONZERO) {
    // Inside if winding ≠ 0; coverage scales with how "full" the pixel is.
    coverage = clamp(abs(winding), 0.0, 1.0);
} else {
    // EvenOdd: triangle-wave on |winding| → 0 at evens, 1 at odds.
    float w = abs(winding);
    coverage = 1.0 - abs(mod(w, 2.0) - 1.0);
}
```

Formula kanonik yang diekstraksi:

| Fill rule | Identifier (nilai) | Formula coverage |
|-----------|--------------------|-------------------|
| NonZero  | `FILL_RULE_NONZERO = 0u` (baris 20)  | `coverage = clamp(abs(winding), 0.0, 1.0)` (baris 215) |
| EvenOdd  | `FILL_RULE_EVENODD = 1u` (baris 21)  | `coverage = 1.0 - abs(mod(abs(winding), 2.0) - 1.0)` (baris 218-219) |

Catatan ekstraksi:

- `winding` adalah penjumlahan `backdrop + Σ line_box(p0, p1, pixel)` (baris 196-208), sehingga keduanya bekerja pada nilai winding **kontinu** (float), bukan integer; karena itu komentar baris 211 menyebut bahwa "*the threshold becomes a clamp*."
- Pemilihan fill rule diekstrak dari *paint flag* dengan operasi bit `(v_paint_flag & FILL_RULE_MASK) >> FILL_RULE_SHIFT` (baris 176), di mana `FILL_RULE_MASK = 0x07000000u` (baris 18) dan `FILL_RULE_SHIFT = 24u` (baris 15). Jadi nilai `fill_rule` di shader cocok dengan kode bit per-tile yang dikemas oleh CPU.

## 4. Fragment shader memproses semua ubin nontrivial pada satu jalur kode tanpa cabang berbasis tipe ubin

Konfirmasi diperoleh dengan membaca seluruh tubuh `void main()` pada `src/render/shaders/render_tile.frag` baris 175-228. Jalur kontrol fragment shader adalah lurus dan tunggal:

1. Baris 176-178 — ekstraksi `fill_rule`, `seg_offset`, `seg_count` dari atribut per-tile (`v_paint_flag`, `v_segment`).
2. Baris 188-189 — perhitungan posisi piksel tile-lokal (`pixel`) dan `scanline_row`.
3. Baris 195-196 — konversi backdrop 8.8 fixed-point ke float dan inisialisasi `winding`.
4. Baris 203-208 — *loop* sekuensial `for (uint s = 0u; s < seg_count; s++)` yang menjumlahkan `line_box(p0, p1, pixel)` untuk setiap segmen yang di-bin ke ubin ini. Ketika `seg_count == 0u`, loop ini tidak tereksekusi sama sekali, sehingga ubin yang sepenuhnya solid (hanya backdrop) dan ubin yang berisi banyak garis melewati cabang program yang sama persis.
5. Baris 213-220 — pemilihan formula `coverage` berdasarkan `fill_rule` (NonZero atau EvenOdd). Cabang ini adalah cabang fill rule, **bukan** cabang tipe ubin; nilainya diekstrak dari paint flag yang sama untuk seluruh ubin terlepas dari klasifikasi geometri.
6. Baris 222-224 — `discard` dipakai sebagai pendek-jalur ketika `coverage <= 0.0`; ini optimasi piksel-level, bukan dispatch tipe ubin.
7. Baris 226-227 — pewarnaan akhir dengan premultiplied alpha.

Pencarian ekstensif konfirmasi tidak ada token klasifikasi tipe ubin di seluruh berkas:

- Pencarian regex `switch|TileType|INTERIOR|EDGE|EMPTY|tile_type` pada `render_tile.frag` tidak menemukan kemunculan operasional; satu-satunya kecocokan substring ada di komentar prosa (`render_tile.frag:128` — kata "*edges*" pada deskripsi tent kernel; `render_tile.frag:199` — kata "*Switching*"). Tidak ada pernyataan `switch` dan tidak ada cabang `if/else` yang bergantung pada penanda tipe ubin.
- Cabang `if` yang ada di seluruh berkas hanya: `line_box` baris 91, 95, 103 (kondisi geometris pada pasangan endpoint), `read_backdrop` baris 77-79 (gather *branchless ternary* pada ivec4), `main` baris 213 (fill rule NonZero vs. EvenOdd) dan baris 222 (`discard` saat coverage nol). Tidak satu pun bergantung pada label tipe ubin (interior, edge, empty, dst.).
- `v_paint_flag` di-decode hanya untuk fill rule (baris 176). Field `paint_and_rect_flag` per-tile (44-byte layout — lihat fakta 1.4) yang memuat penanda persegi di-bit-shift atas tidak diuji oleh fragment shader untuk memilih cabang kode; ia diteruskan begitu saja sebagai atribut.

Vertex shader `src/render/shaders/render_tile.vert` (76 baris) juga tidak memuat percabangan tipe ubin: ia hanya memetakan corner instanced quad ke NDC, meneruskan seluruh atribut (`a_backdrop_lo`, `a_backdrop_hi`, `a_segment`, `a_misc`) ke output `flat`, dan menerapkan satu cabang opsional `if (u_negate_ndc != 0u)` (baris 65-67) untuk membalik orientasi-y NDC. Cabang ini bersifat global (per-frame uniform), bukan per-tile-type.

Konklusi yang dapat dirujuk Subbab 3.4.2/3.4.3/3.4.5:

> Fragment shader Arabella memproses **seluruh ubin nontrivial pada satu jalur kode** yang sama: inisialisasi backdrop → loop akumulasi `line_box` → pemilihan formula coverage berdasarkan fill rule → `discard` opsional saat coverage nol → pewarnaan premultiplied. Tidak ada `switch`, tidak ada `if` berbasis tipe ubin, tidak ada penanda `INTERIOR/EDGE/EMPTY`. Variasi perilaku antar ubin sepenuhnya didorong data: jumlah segmen `seg_count`, isi backdrop per scanline, dan bit `fill_rule` di paint flag.
