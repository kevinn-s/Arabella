## 1. Resolusi DPR-aware pada demo native

Demo interaktif menentukan ukuran kanvas WebGL dari `inner_width × devicePixelRatio`
dan `inner_height × devicePixelRatio` saat `target_arch = "wasm32"`. Cuplikan
verbatim dari `examples/native_webgl/src/main.rs`:

```rust
// examples/native_webgl/src/main.rs
22:        let window = web_sys::window().unwrap();
23:        let dpr = window.device_pixel_ratio();
24:        let inner_w = window.inner_width().unwrap().as_f64().unwrap();
25:        let inner_h = window.inner_height().unwrap().as_f64().unwrap();
26:        let width = (inner_w * dpr) as u16;
27:        let height = (inner_h * dpr) as u16;
```

- Baris 23 (`device_pixel_ratio()`) menyediakan `dpr` (rasio piksel perangkat).
- Baris 24 (`inner_width()`) dan baris 25 (`inner_height()`) memberi ukuran
  viewport browser dalam CSS pixel sebagai `f64`.
- Baris 26–27 menghitung ukuran kanvas piksel-perangkat dengan rumus
  `width = inner_width × devicePixelRatio` dan
  `height = inner_height × devicePixelRatio`, lalu di-cast ke `u16`
  untuk diteruskan ke `run_interactive(width, height)` pada blok
  `wasm_bindgen_futures::spawn_local` di bawahnya.

Konsekuensi narasi: resolusi default demo bersifat **window-fill DPR-aware**,
bukan resolusi tetap. Klaim resolusi default 1920×1080 pada draf lama tidak
selaras dengan source code.

Pada handler resize di `examples/native_webgl/src/lib.rs` rumus yang sama
digunakan ulang:

```rust
// examples/native_webgl/src/lib.rs (handler resize)
            let dpr = win.device_pixel_ratio();
            let iw = win.inner_width().unwrap().as_f64().unwrap() as u32;
            let ih = win.inner_height().unwrap().as_f64().unwrap() as u32;
            let w = ((iw as f64) * dpr) as u32;
            let h = ((ih as f64) * dpr) as u32;
```

Sehingga rumus DPR-aware berlaku baik saat boot maupun saat window resize.

## 2. Empat metrik overlay FPS pada demo native

Fungsi penyusun string overlay FPS bernama persis `update_overlay`, didefinisikan
sebagai metode pada `impl AppState` di `examples/native_webgl/src/lib.rs`:

```rust
// examples/native_webgl/src/lib.rs
316:    fn update_overlay(&self) {
317:        let avg_dt = if self.fps_window.is_empty() {
318:            0.0
319:        } else {
320:            self.fps_window.iter().sum::<f64>() / self.fps_window.len() as f64
321:        };
322:        let fps = if avg_dt > 0.0 { 1000.0 / avg_dt } else { 0.0 };
323:
324:        let asset = &self.assets[self.current];
325:        let scale_x = self.view.m11.hypot(self.view.m12);
326:        let html = format!(
327:            "<b>arabella</b> &nbsp; <span style='color:#9cf'>{}</span><br/>\
328:             FPS: <b>{:>5.1}</b> ({:>5.2} ms)<br/>\
329:             CPU: {:>5.2} ms &nbsp; GPU: {:>5.2} ms<br/>\
330:             zoom: {:.2}× &nbsp; ops: {}<br/>\
331:             <span style='color:#aaa'>drag pan · wheel zoom · space reset · ←/→ scene</span>",
332:            asset.name,
333:            fps,
334:            avg_dt,
335:            self.last_cpu_ms,
336:            self.last_gpu_ms,
337:            scale_x,
338:            asset.paint_ops.len(),
339:        );
340:        self.fps_overlay.set_inner_html(&html);
341:    }
```

Empat metrik enumeratif yang dipancarkan overlay (sesuai AC 9.3):

| # | Metrik (narasi Bab 3)               | Sumber data di kode                                | Tipe / satuan       |
|---|--------------------------------------|----------------------------------------------------|---------------------|
| 1 | Waktu pra-pemrosesan CPU (ms)        | `self.last_cpu_ms` (lib.rs:335)                    | `f64`, milidetik    |
| 2 | Waktu render GPU (ms)                | `self.last_gpu_ms` (lib.rs:336)                    | `f64`, milidetik    |
| 3 | Jumlah operasi paint frame saat ini  | `asset.paint_ops.len()` (lib.rs:338)               | `usize`, ≥ 0        |
| 4 | Rasio zoom (skala viewport efektif)  | `scale_x = self.view.m11.hypot(self.view.m12)` (lib.rs:325, dipakai di lib.rs:337) | `f32` riil positif |

Catatan pendukung (read-only):

- Field-field metrik dideklarasikan di struct `AppState`:
  - `last_cpu_ms: f64` (lib.rs:231)
  - `last_gpu_ms: f64` (lib.rs:232)
- `last_cpu_ms` dan `last_gpu_ms` ditulis pada akhir `AppState::render`
  (lib.rs:297–298) dari selisih `performance.now()` mengelilingi blok
  pra-pemrosesan CPU (`scene.fill` / `scene.stroke`) dan blok rasterisasi GPU
  (`renderer.render`).
- `update_overlay` dipanggil dari `AppState::render` setiap 10 frame
  (`if self.frame_counter % 10 == 0 { self.update_overlay(); }`, lib.rs:312–314)
  untuk menjaga keterbacaan DOM, bukan tiap frame.
- Format string juga menampilkan `FPS` (turunan dari `avg_dt`) dan nama asset,
  namun keempat metrik wajib menurut AC 9.3 adalah CPU ms, GPU ms, jumlah paint,
  dan rasio zoom.

## 3. Konstanta resolusi pengujian wasm-bindgen-test

Pengujian renderer pada `tests/test.rs` mendeklarasikan resolusi kanvas tetap
melalui konstanta lokal di dalam fungsi `test_renders_tiger_svg`:

```rust
// tests/test.rs
146:
147: #[wasm_bindgen_test]
147: async fn test_renders_tiger_svg() {
149:     console_error_panic_hook::set_once();
150:     let _ = console_log::init_with_level(log::Level::Debug);
151:     const W: u16 = 1080;
152:     const H: u16 = 520;
```

> Catatan ekstraksi: deklarasi `#[wasm_bindgen_test]` (baris 147) dan
> `async fn test_renders_tiger_svg()` (baris 147 di sumber) ditampilkan
> berdampingan; lihat berkas asli untuk format persisnya.

Penjelasan:

- `W: u16 = 1080` dideklarasikan di `tests/test.rs` baris 151.
- `H: u16 = 520` dideklarasikan di `tests/test.rs` baris 152.
- Keduanya di-cast ke `u32` ketika diteruskan ke `RenderSize { width: W as u32, height: H as u32 }`
  serta `create_canvas(W as u32, H as u32, 1.0)` di tubuh tes yang sama.

Resolusi pengujian kanonik untuk Subbab 3.6 adalah **1080 × 520 piksel**,
bukan 1920 × 1080 seperti pada draf lama.

Catatan tambahan (informasional, tidak dipakai untuk klaim AC 9.4):

- Berkas yang sama juga memuat fungsi `test_renders_circle` (baris 236) yang
  mendeklarasikan `const W: u16 = 400` (baris 240) dan `const H: u16 = 400`
  (baris 241), namun atribut `#[wasm_bindgen_test]` di atasnya dikomentari
  (baris 235: `// #[wasm_bindgen_test]`), sehingga fungsi tersebut tidak
  dieksekusi sebagai pengujian aktif. Resolusi 1080 × 520 adalah satu-satunya
  resolusi pengujian wasm-bindgen-test yang aktif.

## Ringkasan untuk Subbab 3.6

1. Demo `examples/native_webgl/` memakai resolusi window-fill DPR-aware:
   `width = inner_width × devicePixelRatio`,
   `height = inner_height × devicePixelRatio`
   (`examples/native_webgl/src/main.rs:23–27`).
2. Overlay FPS demo menampilkan empat metrik enumeratif — waktu CPU (ms),
   waktu GPU (ms), jumlah operasi paint frame saat ini, dan rasio zoom
   — disusun oleh fungsi `update_overlay` pada
   `examples/native_webgl/src/lib.rs:316–341`.
3. Pengujian wasm-bindgen-test pada `tests/test.rs` memakai resolusi kanvas
   tetap 1080 × 520 piksel via konstanta `W: u16 = 1080` (baris 151) dan
   `H: u16 = 520` (baris 152) di dalam fungsi `test_renders_tiger_svg`
   (deklarasi `#[wasm_bindgen_test]` pada baris 147).
