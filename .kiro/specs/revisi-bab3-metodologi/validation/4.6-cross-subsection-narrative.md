## 1. Metodologi Pemeriksaan

Empat dimensi dipindai untuk setiap subbab:

1. **Branching style** — apakah subbab mengklaim percabangan tipe ubin (kontradiksi) atau jalur kode tunggal (konsisten).
2. **Tile field reference style** — apakah subbab mereferensikan `winding_number` skalar / enum `TileType` (kontradiksi) atau `backdrop` array delapan elemen (konsisten dengan source).
3. **Pipeline stage ordering** — urutan tahap yang didukung subbab (jika dieksplisitkan).
4. **Pipeline component identity** — apakah komponen pipeline (flattening, outer/inner DDA, signed-area, propagasi backdrop, vertex shader, fragment shader) disebut dengan nama kanonik yang sama.

Pencarian pendukung yang dijalankan pada `Skripsi/bab3_metodologi.md`:

| Pola pencarian | Hasil |
|---|---|
| `winding_number` (token persis dengan underscore) | 0 kemunculan di seluruh berkas |
| `TileType` | 0 kemunculan |
| `INTERIOR`, `EDGE`, `EMPTY`, `ray_shoot` (case-insensitive) | 0 kemunculan |
| `backdrop` (case-insensitive) | banyak kemunculan, semuanya konsisten dengan struktur array delapan elemen |
| `[i16; 8]` / `[i16; TILE_H]` / "delapan akumulator" / "array delapan elemen" | hadir di 3.4.4 dan 3.5; tidak ada subbab yang mengontradiksi |

Output ringkas seluruh empat dimensi diberikan pada §2 berikut.

## 2. Per-Subsection Summary

### 2.1 Subbab 3.4.2 (Use Case Description, UC-03 Basic Flow)

**(a) Branching style.**
Subbab ini menyatakan eksplisit:

> *"Fragment shader analitik tunggal yang sama dijalankan untuk seluruh ubin nontrivial melalui satu jalur kode tanpa percabangan kondisional berbasis tipe ubin."* (baris 135)

Tidak ada penyebutan "klasifikasi ubin", "Render Warna Solid", atau "Evaluasi Fungsi Implisit". → **Konsisten dengan jalur kode tunggal.**

**(b) Tile field reference style.**
Subbab ini menyebut "delapan akumulator 16-bit per ubin, satu per scanline" dan "rekord vertex buffer instanced beserta segmen tile-lokal pada tekstur RGBA32F" (baris 135). Tidak ada `winding_number` skalar atau enum `TileType`. → **Konsisten dengan backdrop array delapan elemen.**

**(c) Pipeline stage ordering (eksplisit).**
Urutan dieksplisitkan sebagai (a)-(f) untuk tahap CPU dan (i)-(ii) untuk tahap GPU pada baris 135:

| Label | Tahap |
|---|---|
| (a) | Flattening kurva Bézier → segmen garis F24Dot8 |
| (b) | Outer DDA (lintas baris ubin) |
| (c) | Inner DDA (lintas kolom ubin) |
| (d) | Akumulasi signed-area per scanline (8.8 fixed-point) |
| (e) | Emisi ubin nontrivial |
| (f) | Propagasi backdrop kiri-ke-kanan (saat emisi berlangsung) |
| (i) | Vertex shader instanced quad |
| (ii) | Fragment shader analitik tunggal |

**Sesuai persis dengan urutan kanonik pada deskripsi tugas:** flattening → outer DDA → inner DDA → akumulasi signed-area → emisi ubin → propagasi backdrop → vertex shader → fragment shader.

Catatan: subbab ini eksplisit menyebut "**Saat** emisi berlangsung pada setiap baris ubin, pustaka mempropagasikan backdrop kiri-ke-kanan", yang mengomunikasikan bahwa (e) dan (f) bersifat interleaved dalam satu loop, bukan dua tahap berurutan strict.

**(d) Pipeline component identity.**
Komponen disebut dengan nama kanonik: `flattening`, `outer DDA`, `inner DDA`, `signed-area`, `propagasi backdrop`, `vertex shader instanced quad`, `fragment shader analitik tunggal`, `line_box`, `NonZero`, `EvenOdd`, `F24Dot8`, `8.8 fixed-point`, `RGBA32F`, `16×8 piksel`. → **Konsisten.**

### 2.2 Subbab 3.4.3 (Sequence Diagram)

**(a) Branching style.**
Subbab ini menyatakan eksplisit pada paragraf pengantar:

> *"Karena pipeline hibrida Arabella memproses seluruh ubin nontrivial melalui satu jalur kode tunggal tanpa percabangan kondisional berbasis tipe ubin, sequence diagram disusun sebagai lima pesan berurutan tanpa blok alternatif (`alt`), opsional (`opt`), maupun perulangan (`loop`) yang bercabang berdasarkan klasifikasi ubin."* (baris 139)

Pesan 3 (Scene → Builder: generate_tiles) menyatakan emisi seluruh ubin "melalui satu jalur kode tunggal tanpa percabangan tipe ubin" (baris 148). Pesan 5 (WebGlRenderer → GPU) menyatakan fragment shader dijalankan "pada satu jalur kode tanpa percabangan kondisional berbasis tipe ubin" (baris 154). → **Konsisten dengan jalur kode tunggal.**

**(b) Tile field reference style.**
Subbab ini menyebut "vektor `Vec<Tile>`" (baris 148), "vertex buffer instanced melalui `scene.tiles()`", "tekstur segmen RGBA32F melalui `scene.segments()`" (baris 152), serta "backdrop per scanline" (baris 154). Tidak ada `winding_number` skalar atau enum `TileType`. → **Konsisten dengan backdrop array delapan elemen** (tidak ada deklarasi struktural kontradiktif).

**(c) Pipeline stage ordering.**
Urutan dieksplisitkan sebagai lima pesan; di dalam pesan 2 dan 3 ada urutan internal:

| Pesan | Stage internal |
|---|---|
| 1 | `Scene::fill` / `Scene::stroke` (penyerahan jalur) |
| 2 | `Builder::build_path`: flattening → binning DDA (outer + inner) → akumulasi signed-area per scanline |
| 3 | `Builder::generate_tiles`: propagasi backdrop kiri-ke-kanan **lalu** emisi seluruh ubin nontrivial |
| 4 | `WebGlRenderer::render` menerima vertex buffer dan tekstur segmen |
| 5 | Vertex shader instanced quad → fragment shader analitik tunggal |

Urutan global: flattening → outer DDA → inner DDA → signed-area → propagasi backdrop → emisi → vertex → fragment.

**Observasi penting:** di Pesan 3, urutan tekstual `propagasi backdrop` mendahului `emisi`, sedangkan di 3.4.2 urutan label adalah (e) emisi → (f) propagasi backdrop. **Ini bukan kontradiksi pipeline:** kedua subbab sama-sama menempatkan kedua langkah di dalam method tunggal `Builder::generate_tiles` dan sama-sama mendeskripsikan sifat interleaved (3.4.2 dengan klausa "Saat emisi berlangsung", 3.4.3 dengan kalimat tunggal yang mendeskripsikan kedua aksi sebagai bagian dari satu pesan). Komponen pipeline-nya identik; yang berbeda hanya pemilihan urutan kalimat untuk mendeskripsikan satu loop yang sama.

**(d) Pipeline component identity.**
Komponen disebut dengan nama kanonik yang identik dengan 3.4.2: `flattening`, `outer DDA`, `inner DDA`, `signed-area`, `propagasi backdrop`, `vertex shader instanced quad`, `fragment shader analitik tunggal`, `line_box`, `NonZero`, `EvenOdd`, `F24Dot8`, `8.8 fixed-point`, `RGBA32F`, `16×8 piksel`. → **Konsisten.**

### 2.4 Subbab 3.5 (Perancangan Algoritma)

**(a) Branching style.**
Paragraf pembuka subbab (baris 278) menyatakan:

> *"Variasi perilaku antar ubin pada tahap GPU sepenuhnya didorong data — jumlah segmen yang di-binning, isi backdrop per scanline, dan bit fill rule pada `paint_and_rect_flag` — sehingga seluruh ubin nontrivial diproses fragment shader tunggal melalui jalur kode yang sama tanpa cabang `if`/`switch` berbasis kategori ubin."*

Sub-bagian (f) menambahkan: "cabang ini hanya bergantung pada bit fill rule, bukan pada kategori ubin" (baris 312). → **Konsisten dengan jalur kode tunggal.**

**(b) Tile field reference style.**
Sub-bagian (c) merujuk `CoverStorage::backdrops: Vec<[i16; TILE_H]>` (baris 292). Sub-bagian (d) merujuk `acc_arr: [i16; 8]` dan `Tile.backdrop = acc_arr` (baris 296). Tidak ada `winding_number` skalar atau enum `TileType` di mana pun. → **Konsisten dengan backdrop array delapan elemen.**

**(c) Pipeline stage ordering (eksplisit melalui sub-bagian (a)-(f) plus paragraf pembuka).**
Paragraf pembuka (baris 278) menyatakan: *"Pipeline hibrida Arabella memecah pekerjaan rendering geometri dua dimensi menjadi enam tahap CPU yang berurutan diikuti oleh dua tahap GPU."*

Urutan sub-bagian:

| Label | Tahap |
|---|---|
| (a) | Flattening Kurva (cubic-to-quadratic + quadratic-to-garis pada F24Dot8) |
| (b) | Binning DDA Dua Tahap (outer DDA + inner DDA) |
| (c) | Akumulator Signed-Area per Scanline pada 8.8 Fixed-Point |
| (d) | Propagasi Backdrop Kiri-ke-Kanan (di dalam `Builder::generate_tiles`, interleaved dengan emisi) |
| (e) | Evaluasi Cakupan Piksel di GPU melalui Integral Trapezoidal `line_box` (fragment shader; vertex shader instanced quad disebut implisit) |
| (f) | Penerapan Fill Rule NonZero (Clamp Absolute) dan EvenOdd (Triangle Wave) |

Sub-bagian (d) menjelaskan emisi dan propagasi backdrop sebagai dua aksi yang terjadi di dalam loop `Builder::generate_tiles` yang sama: "Saat ubin diemisi, `Tile.backdrop = acc_arr` ditulis terlebih dahulu — yaitu nilai akumulator sebelum kontribusi cell ini ditambahkan — sehingga backdrop yang diunggah ke GPU mencerminkan sumbangan kumulatif dari seluruh kolom di sebelah kirinya." (baris 296)

**Urutan global yang disebut subbab ini:** flattening → outer DDA → inner DDA → akumulasi signed-area → propagasi backdrop dan emisi (interleaved) → vertex shader (implicitly via instanced quad) → fragment shader.

**Sesuai dengan urutan kanonik;** seperti pada 3.4.3, pasangan (emisi, propagasi backdrop) disajikan sebagai proses interleaved di satu method generate_tiles, yang merupakan deskripsi akurat dari implementasi.

**(d) Pipeline component identity.**
Komponen disebut dengan nama kanonik yang identik: `flattening`, `outer DDA`, `inner DDA`, `signed-area`, `propagasi backdrop`, `fragment shader`, `line_box`, `NonZero`, `EvenOdd`, `F24Dot8`, `8.8 fixed-point`, `RGBA32F`, `16×8 piksel`, `TILE_W = 16`, `TILE_H = 8`, `WINDING_UNIT = 256`. → **Konsisten.**

## 5. Verdict Keseluruhan

**STATUS: PASS**

Keempat subbab (3.4.2, 3.4.3, 3.4.4, 3.5) konsisten satu sama lain pada:

1. **Branching style** — 3.4.2, 3.4.3, dan 3.5 secara eksplisit menyatakan jalur kode tunggal tanpa percabangan tipe ubin; 3.4.4 tidak menyajikan klaim kontradiktif.
2. **Tile field reference style** — `backdrop: [i16; 8]` (4 subbab konsisten), tidak ada `winding_number` skalar atau enum `TileType` di mana pun.
3. **Pipeline component identity** — istilah kanonik (flattening, outer DDA, inner DDA, signed-area, propagasi backdrop, vertex shader instanced quad, fragment shader analitik tunggal, line_box, NonZero, EvenOdd, F24Dot8, 8.8 fixed-point, RGBA32F, 16×8 piksel) digunakan identik.
4. **Pipeline stage ordering** — urutan tahap kanonik (flattening → outer DDA → inner DDA → akumulasi signed-area → {emisi + propagasi backdrop di `Builder::generate_tiles`} → vertex shader → fragment shader) konsisten di seluruh subbab. Subbab 3.4.2 menempatkan emisi sebelum propagasi backdrop dengan klausa interleaving; 3.4.3 dan 3.5 menempatkan propagasi sebelum emisi; ketiganya merujuk satu method dan satu loop yang sama, sehingga perbedaan urutan kalimat bukan kontradiksi pipeline.

Property 6 **PASS**.
